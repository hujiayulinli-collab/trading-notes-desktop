# 盘口手记

一个交易记录与 GPT 复盘工具。支持交易手记、截图、统计、AI 复盘、自定义入场条件、本地资料库，以及使用 Supabase 登录的云端资料库。完整备份可在本地和云端之间导入导出。

云端首次使用请阅读 [免费云端设置说明](supabase/开始使用云端.md)。需要先创建你自己的 Supabase 项目，执行建库文件，再填写项目地址与公开连接密钥；尚未连接真实云项目。

## 日常使用

双击 **启动盘口手记.cmd**，浏览器会打开 [盘口手记](http://127.0.0.1:4319/)。关闭浏览器后，本地服务仍会运行；关机后，下次再双击启动。

同一 Wi-Fi／路由器下的另一台电脑使用：双击 **启动盘口手记（局域网）.cmd**，窗口会显示 `http://主机局域网IP:4319/`。首次需要在主机右键 **配置局域网访问.cmd → 以管理员身份运行**，为当前网卡的同网段设备放行这一端口。两台电脑访问同一份资料库，改动都保存在主机；主机需保持开机且不休眠。普通启动文件会切回仅本机模式，切换前请等页面显示已保存。

局域网模式仅供可信家庭／办公网络使用，同网段内被允许访问的设备均可读写手记，没有额外登录认证。服务校验网卡 IP、同网段来源和同源请求；修改主机数据保存目录仅允许在主机页面操作。不要做路由器公网端口映射。更多说明见 [开始使用](docs/开始使用.md)。

首次使用展示独立的示例手记，示例及其改动不会写入真实资料库。点击“记录交易”开始，或在设置中导入备份。新电脑请先按 [开始使用](docs/开始使用.md) 完成安装与构建。

1. 记录品种、入场日期与时间，选择方向、周期、时段和持仓状态。
2. 勾选入场条件；点“自定义”可添加、改名、删除和调整模块顺序，也可编辑每个模块的条件。例如将 FVG 改成 OB。最多 20 个模块，电脑端每行 4 个，窄屏自动换列；每模块最多 50 个条件。旧交易已记录的条件文字会保留。填写价格、风险比例与入场次数。
3. 点击、拖入或粘贴截图。支持 PNG / JPG / WEBP，每笔最多 8 张，单张不超过 8 MB、4,000 万像素。保存原图，可标记入场、持仓、离场并放大查看。
4. 在“03 交易复盘”中填写入场打分（0–100 分，可填小数或留空）、进场依据、执行过程、做对与做错、下次改进。评分是你对入场质量的自评，随手记、完整备份及新周报告保存，旧记录显示未评分。
5. 平仓后将状态改为“已平仓”，填写净结果 R。页面上方设置“基础 1R = … %”，点击“应用”后自动保存并重算累计收益、平均每笔和统计图表，默认 1%。例如风险 2%、结果 −1R、基础 R 为 1%，统计收益为 −2R；原始结果仍为 −1R。

“记录类别”区分实盘过程中记录的单与周复盘时整理的单。打开新建窗口时，按 **UTC+8** 判断：周六、周日默认“复盘”，其余默认“实盘”；可以手动修改，修改交易日期不会重算类别。旧记录显示“未分类”，可逐笔补选。页面上方可按类别筛选，列表、顶部指标和统计页会使用同一类别范围。

勾选入场条件后，“进场依据”自动按 **趋势，FVG + 背离，入场** 的顺序填写，例如 `15m 顺势，15m FVG + 15m 背离，1m 吞没FVG`。原模块改名后保留这个自动填写位置；新增模块按页面顺序补在其后。空模块自动省略，未归组的旧条件放在最后。未手动编辑前，继续勾选或取消会更新自动文字；手动补充、改写或主动清空后，不再自动覆盖。已有手写笔记会保留。

有效编辑约 650 毫秒后自动保存。以顶部 **已保存到本地 / 已保存到云端** 为准；有未保存更改时，刷新或关闭页面会提示。保存失败时保留页面中的草稿，可以重试或下载未保存文字。该文字草稿用于故障恢复阅读，不是含截图的完整备份。自定义选项属于当前真实资料库，即使在示例手记中打开条件设置，也会保存这些选项。

## 文件保存与换电脑

默认保存位置是项目内的 **data** 文件夹：

- `journal.json`：交易、笔记、截图引用、自定义条件选项、基础 R 与 GPT 复盘结果。
- `screenshots/`：原始截图。
- `journal.previous.json`：上一次成功保存前的记录快照。
- `.journal.lock`：资料库的进程锁，防止多个程序同时覆盖数据。

设置中可输入一个新的**绝对路径的空文件夹**。程序会复制记录和图片、校验成功后切换保存位置；原文件夹保留。保存位置写在项目的 `.local-settings.json` 中。

换电脑建议使用“导出完整备份”。导出的 JSON 包含所有交易、原图和 GPT 复盘，不包含 API Key。新电脑准备好程序后，进入设置 → 导入备份 → 检查新增／重复数量 → 确认导入。相同 ID 的交易默认跳过，不会覆盖新电脑已有的记录。

备份文件上限为 200 MB。资料较大时，退出程序后复制整个数据文件夹；在新电脑将其放在项目的 `data` 目录，且不要沿用旧电脑的 `.local-settings.json`。不要只复制 `journal.json`，否则会缺少截图。删除手记会移除记录和图片引用，磁盘原图暂时保留以供恢复；完整备份只包含仍被记录引用的图片。

如果 `journal.json` 损坏或丢失，先保留整个资料库副本，再检查 `journal.previous.json`；关闭服务后可以将该文件复制为 `journal.json` 恢复前一版。程序不会自动用空资料覆盖发现的恢复文件。

## GPT 复盘

**直接用 ChatGPT：** 点“复制资料到 ChatGPT”，复制整理好的交易资料后粘贴到 ChatGPT。文本中的截图清单不等于图片，需在 ChatGPT 中另行添加截图。统计页也可整理指定日期范围的批量复盘文字。

**页面内调用 GPT：** 在设置填写 OpenAI API Key 和账户可用的 GPT 模型，默认 `gpt-5.4-mini`。点击“请 GPT 复盘”才会发送当前交易；可选择是否包含截图。密钥只保留在当前页面内存，刷新后需重填，不写入磁盘或备份。模型回复会保存到该交易，记录修改后会标记复盘需要更新。

请求使用 [OpenAI Responses API 的图文输入](https://developers.openai.com/api/docs/guides/images-vision)。API 按 OpenAI 账户独立计费，需要有效密钥、额度和网络连接。实际模型调用尚未用真实密钥验证；自动测试使用模拟回复检查请求内容、失败提示与并发处理。

AI 复盘只整理提供的事实并指出执行问题，不连接行情、不交易、不宣称预测未来表现。交易备注、截图文字和导入内容均作为待分析资料，与复盘指令分开。

## 周总结：交给 Codex 分析并生成 HTML

1. 打开顶部 **周总结**，选择开始/结束日期和记录类别，再逐笔勾选本次要交给老师的手记。本周和上周按 UTC+8 的周一至周日计算，筛选使用手记里的入场日期，包含起止两天。默认选择本周实盘，也可选择复盘或混合类别。
2. 点击 **准备 Codex 复盘资料**。程序先保存当前修改，再冻结所选记录及其原图；不会导出未选择的手记。每份最多 100 笔，含图片编码的资料不超过 100 MB，缺失或损坏的截图会阻止准备。此步骤只整理本机资料，不需要 API 密钥，也不会调用 GPT API。
3. 点击 **复制复盘指令**，粘贴到此项目的 Codex 对话。Codex 按资料包中的说明查看截图、分析交易，写入 `analysis.json`，再执行 `node scripts/build-weekly-report.mjs 报告编号` 生成报告。剪贴板不可用时，可手动复制页面中的指令文本。准备资料本身不等于已完成 AI 分析。
4. 回到页面点 **刷新报告状态**，已完成的报告可 **下载 HTML**。下载的是单个文件，带原始笔记、逐笔分析和完整内嵌截图；老师无需访问你的电脑、登录云账号或联网加载图片。打开后可放大截图，也可打印或保存为 PDF。

已准备的资料、原图和历史报告继续保留。之前 API 分析未完成的资料也能复制 Codex 复盘指令，无需重新整理；真正仍在运行的旧任务需先等待结束再刷新。下载前仍会校验报告文件，不会把不完整文件当成已完成报告。

本机报告支持 **归档 / 恢复 / 删除**。归档后移入“已归档”列表，原文件与复盘指令路径不变，仍可下载，也可恢复到“当前报告”。删除需要确认，会永久清理这一份报告的 HTML、分析、手记快照及截图副本；不会删除原始资料库、其他报告或已经下载到其他位置的文件。报告正在生成或处理时不能删除；归档状态会保存在本机，重启后仍保留。

报告包含总体结论、分类统计、最多三项下周计划、逐笔记录和截图、向老师请教的问题，以及明确的分析局限。实盘、复盘、未分类分别统计；只对实际查看过的截图标记已核对。笔记和 AI 文本经过转义，不会作为网页代码执行。

资料与报告保存在项目的 `weekly-reviews/generated/报告编号/`，原始手记以后修改或删除不会影响这份快照。新报告同时冻结当时的基础 R；没有基础 R 字段的历史快照沿用原始 R 统计。报告目前保存在本机：即使手记来自云账号，报告也会单独留在当前电脑。换电脑时请一起复制这个目录，或先下载需要的 HTML；现有“完整备份”仅包含资料库，不包含这个报告目录。旧的手工制作周报保持原样，不会自动出现在新的报告列表。

## 统计口径

- 有效平仓：状态已平仓且结果 R 为有效数值。未填 R 是空值，不能当作保本。
- R = 已实现净盈亏 ÷ 初始计划风险金额；包括费用，移动止损不改变原始分母。当前版本直接填写 R，价格只作记录，不推算分批进出的收益。
- 胜率 = 盈利笔数 ÷ 有效平仓笔数；保本计入分母，持仓与观察不计入。
- 换算收益 R = 风险比例 ÷ 基础 R 比例 × 原始结果 R；累计收益为换算值之和，平均每笔为换算值之和 ÷ 可换算平仓笔数。风险未填或为 0 的平仓记录暂不计入收益、均值、盈亏比和回撤，仍参与胜率和纪律统计；没有可换算记录时显示“—”。
- 基础 R 随资料库保存、备份和云端同步。旧库默认 1%；空库导入带基础 R 的备份时恢复其设置，合并到已有手记的资料库时保留当前基础 R。
- 守纪律率仅统计已平仓且已评价的记录，未评价不会默认为遵守。
- 平均盈亏比 = 平均盈利 R ÷ 平均亏损绝对 R；缺少相应样本时显示“—”。
- 曲线与回撤按入场日期、时间排序，不代表账户资金或实际平仓时序。
- 顶部按所选记录类别统计；统计页可以进一步限定日期范围。类别表示记录场景，不改变持仓状态或 R 的计算。标签分组可能重叠，不能把各组相加视为总数。

## 重新安装与开发

适用于 Windows。新电脑需安装 Node.js 22.18+（或 Node.js 24）及 pnpm 11，之后双击“安装与构建.cmd”。完成后双击“启动盘口手记.cmd”。默认仅本机访问，局域网启动入口可开启同网段访问。

安装及分享说明见 [开始使用](docs/开始使用.md)。启动脚本可读取本机自行配置的 `.local-runtime.json`，没有此文件时使用已安装的 Node.js 与 pnpm，无需先打开 Codex。普通本地构建不要求提供在线发布配置。

## 分享纯净项目

双击“导出纯净项目.cmd”，会在 `outputs` 下生成源码文件夹和 ZIP。它仅复制明确列入清单的源码、测试、通用文档与 AI 提示词，排除真实手记、截图、历史报告、个人交易规则、本机配置、密钥、日志、安装依赖和构建缓存。请分享新生成的 ZIP，不要直接压缩已经使用过的整个项目。

通用 AI 提示词在 `docs/ai-prompts`：单笔交易复盘、周总结复盘、交易规则填写模板。每次在页面准备周总结时，还会按新用户所选手记生成对应的 `复盘说明.md` 和分析格式说明。

开发命令：`pnpm dev`；正式构建：`pnpm build`；运行：`pnpm start`；数据测试：`pnpm test`；类型检查：`pnpm typecheck`。

架构为 React + TypeScript + Vinext 静态页面，以及 Node.js 本地文件/GPT 服务。开发页面端口 5173，本地数据服务及正式页面端口 4319。云端模式由前端通过 Supabase 官方客户端直接访问 Auth、带账号隔离规则的 PostgreSQL 资料库及私有 Storage；文件备份兼容本地模式。当前尚未发布在线网址。资料夹和私密密钥不提交到版本库。
