# 盘口手记：开始使用

这是一份可以在自己电脑上运行的交易手记项目。源码、功能、通用 AI 提示词和测试齐全，不附带分享者的交易、截图、历史报告、个人交易规则、云账号或本机设置。

## 在相同环境下使用

已验证的环境是 Windows 64 位、Node.js 24.21.0、pnpm 11.19.0。项目要求 Node.js 至少 22.18；为了复现验证结果，建议使用上面的已验证版本。无需安装 Python、Docker 或本地数据库。

1. **完整解压 ZIP** 到自己的文件夹，例如 `D:\Apps\pankou-journal`。不要在压缩包里直接双击启动。
2. 确认 Node.js 与 pnpm 已安装并加入 PATH。新打开的终端运行 `node --version` 与 `pnpm --version`，应显示对应版本。缺少环境时从 [Node.js 官方下载页](https://nodejs.org/en/download) 获取 Node.js；已有 Node.js 后可执行 `npm install --global pnpm@11.19.0`。环境已具备就跳过安装。
3. 双击 **安装与构建.cmd**，等待显示“准备完成”。首次会联网下载锁定版本的依赖；需要能访问 npm 软件仓库。这个包没有预装依赖或构建产物。
4. 双击 **启动盘口手记.cmd**，浏览器会打开 `http://127.0.0.1:4319/`。
5. 点击“记录交易”开始使用自己的资料库。页面可能先展示标有“示例”的内置演示记录；它们是虚构示例，不是分享者的真实交易，也不会自动写入资料库。

关闭浏览器后，本地服务仍运行。关机后，再次双击启动文件即可。不要同时启动同一台电脑上的多份项目：默认端口都是 4319。自己电脑上已经使用过的浏览器可能保留云端连接或登录状态；首次核验纯净包时可使用新的浏览器配置或隐私窗口。

## 将安装与缓存放在 D 盘

可以将官方 Node.js Windows ZIP 解压到 D 盘并把含 `node.exe` 的文件夹加入用户 PATH。以下配置仅用于尚未配置 npm / pnpm 保存位置的电脑；已配置好时无需重复执行：

```powershell
npm config set prefix "D:\DevTools\npm-global"
npm config set cache "D:\DevTools\cache\npm"
```

将 `D:\DevTools\npm-global` 加入用户 PATH，再打开一个终端执行：

```powershell
npm install --global pnpm@11.19.0
pnpm config set store-dir "D:\DevTools\cache\pnpm-store"
pnpm config set cache-dir "D:\DevTools\cache\pnpm"
```

项目文件夹放在 D 盘时，项目依赖和默认数据也位于 D 盘。这里不附带他人的 `.local-runtime.json`，因此不会固定指向分享者的电脑路径。

## 数据、AI 与云端

- **本地资料**：首次运行自动创建 `data`，保存自己的手记与截图。定期在页面导出完整备份。
- **AI 复盘**：`docs/ai-prompts` 下的 Markdown 可以复制使用。将空白规则模板复制到 `weekly-reviews/my-trading-rules.md` 后填写，保留随包模板为空白；这个个人规则目录不会进入下一次纯净导出。未提供规则时，AI 应明确缺失信息。
- **周总结**：页面选择手记范围 → 准备 Codex 复盘资料 → 复制复盘指令到能访问此项目的 Codex 对话。每次生成的 `复盘说明.md` 包含本次资料范围和输出格式。完成后在页面刷新并下载 HTML。该流程不会自动调用项目内 GPT API。
- **页面内 GPT**：如使用此功能，需自行准备有效的 OpenAI API 凭据与额度；项目不提供共享密钥，实际可用模型由自己的 API 账户决定。
- **云端（可选）**：按 `supabase/开始使用云端.md` 创建自己的项目并执行 `setup.sql`。本地使用不需要云端账号。项目不附带任何真实云连接。
- **给别人访问**：本包可让对方独立运行。也可按下文开启局域网模式，让同一路由器内的设备访问主机上的同一份手记；`127.0.0.1` 始终只代表正在使用的那台电脑。

周总结及分析保存在 `weekly-reviews/generated`。完整资料库备份不包含该报告目录；换电脑时另行保留需要的报告或下载 HTML。

## 同一 Wi-Fi／路由器访问

1. 主机已完成安装与构建后，右键 **配置局域网访问.cmd**，选择“以管理员身份运行”。它只允许当前带网关的私网网卡、当前 Node.js 程序和指定 TCP 端口的本地子网访问，不会关闭防火墙。Windows 把家庭网络标为“公用”时也能使用这条受限规则，无需修改整台电脑的网络类型。
2. 等待页面显示已保存，再双击 **启动盘口手记（局域网）.cmd**。若本机模式正在运行，会在确认进程属于此项目后切换模式；窗口会打印当前访问地址。
3. 另一台电脑连接同一路由器，在浏览器输入窗口给出的 `http://主机IP:4319/`。主机插网线、另一台电脑用 Wi-Fi 也可以，只要处于同一局域网。另一台电脑无需安装项目或 Node.js。
4. 主机需保持开机、不休眠，服务持续运行。主机 IP 改变后，重新配置防火墙并以窗口中的新地址访问。双击普通 **启动盘口手记.cmd** 会切回仅本机访问。

两台设备读写的是同一份主机资料。并发编辑沿用版本冲突保护；切换设备前保存，另一个页面刷新后继续编辑。远端“本地保存”指保存在运行服务的主机，数据目录迁移要回到主机的 `127.0.0.1` 页面操作。云端登录状态则保存在各自浏览器中。

此模式信任被放行的同网段设备，包含查看、编辑、完整备份和删除报告等操作，没有额外访问密码。HTTP 未加密，仅用于可信家庭或办公网络，不用于公网发布，不设置路由器公网端口映射。

HTTP 局域网地址支持新建、编辑、上传截图、本地备份及本地周报告。浏览器可能限制自动复制，请按页面提示手工复制；云端备份与云端截图周报告需要浏览器的安全校验能力，请在主机 `127.0.0.1` 页面或 HTTPS 环境操作。[浏览器安全上下文说明](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts)

连接不上时，确认两台设备没有使用隔离的访客 Wi-Fi、路由器未开启设备隔离，并确认主机服务和受限防火墙规则已开启。此项目没有配置公网访问。

## 包内内容

`app`、`components`、`hooks`、`lib`、`public` 是页面与共享逻辑；`server`、`scripts` 是本地服务和构建工具；`tests` 是虚构数据测试；`supabase` 是可选云端建库资料；`docs/ai-prompts` 是通用提示词。`share-manifest.json` 记录包内文件及校验值，方便检查文件完整性。

未包含：真实 `data`、整个历史 `weekly-reviews`、个人环境说明、`.local-*` 配置、`.env`、Git 历史、日志、`node_modules`、`dist` 和各类缓存。

需要再次分享时，双击 **导出纯净项目.cmd**。不要压缩已产生交易数据的整个目录。

## 常见问题

- 找不到 Node.js / pnpm：安装后检查 PATH，并重新打开终端。不要使用旧电脑的绝对路径配置。
- 下载依赖失败：检查网络，然后再次运行“安装与构建.cmd”；保留 `pnpm-lock.yaml`。
- 页面未构建或缺依赖：完整解压后先运行“安装与构建.cmd”。
- 启动失败：查看 `logs/server-error.log`；检查是否有其他项目占用 4319 端口。不要删除资料库来修复启动问题。
- 看见原来的云数据：检查当前浏览器是否已登录其他云账号；纯净包不会携带登录凭据。

可选开发命令：`pnpm test`（功能测试）、`pnpm typecheck`（代码检查）、`pnpm build`（构建）、`pnpm dev`（开发预览）。
